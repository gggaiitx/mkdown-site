# 码克 v0.6.0-patch.2

这一版只做一件事：把启动压下来。上一版把界面欠账清完之后，冷启动的体感成了最扎眼的一项，于是先把启动链路拆开量化，再逐段搬走——首屏必载的 JS 从 2.78MB 降到 330KB，同一台机器实测窗口内容就绪从 508ms 降到 130ms。

## 首屏只加载外壳

- **首屏必载 JS 2.78MB → 330KB，CSS 165KB → 47KB**：`DOMContentLoaded` 实测 508ms → 130ms（冷代码缓存）、394ms → 70ms（热）。窗口出来先看到顶栏、标签栏与目录树，正文随后就位。
- **三个编辑内核改为按需加载**：Markdown / 代码 / 富文本 `.mh` 的内核及其依赖（md-editor-v3、CodeMirror、mermaid、KaTeX、highlight.js）不再进首屏。只开 docx / 图片 / 代码类文件的会话，Markdown 那一整套根本不会被下载。
- **导出与 Word 反转的转换链改点开才取**：`docx`、`mammoth`、`jszip`、`docx-preview` 这些只在导出/转换时才用得到的重依赖，从启动路径上摘掉。
- **撤掉一处打包配置**：原先固定把 md-editor-v3 切成具名 chunk，结果 vue 运行时被吸进那个 chunk，入口为了拿到 vue 仍要整包解析它——内核改成按需加载后被它抵消干净。撤掉之后 `index.html` 只剩一个入口脚本加一份样式。
- 空闲预载补齐三个内核 chunk：首屏不下载内核的代价是「欢迎页点开第一份文档」要现取现评，放进浏览器空闲切片预载抹平，不跟启动抢主线程。

## 启动过程并行化

- **会话标签并发读盘**：上次退出时开着几个标签，恢复就要几次文件读取；改成一次性并发发出。标签排列与活动标签仍严格按上次退出时的顺序，不会因谁先读完而乱序。
- **目录树与标签恢复并行**：整棵工作区树的遍历不再挡在内容区前面，树晚到一帧只是目录树后填一次。
- **Office 全文索引预热挪到空闲**：它在后台按整库并行解压 docx，原先一打开工作区就起跑，正撞在首屏最敏感的时间窗里自己跟自己抢 CPU。
- **设置无变化不再回写**：启动恢复工作区时，`lastWorkspace` 与历史列表本就是上次写进去的值，省掉启动后那次无意义的落盘与全站重渲染。

## 界面与健壮性

- **暗色主题不再白闪**：窗口底色按上次退出时的主题预设好再显示。此前 WebView 出首帧之前那一层是系统白底，而主题要等前端把设置读回来才生效，暗色用户每次启动都先挨一下白。
- **修一处启动隐患**：恢复会话的目录授权（上次工作区 + 最近文件所在目录）从「窗口显示之前」挪到后台线程。这批路径里若有失效网络盘或拔掉的移动硬盘，系统解析单个就能卡数秒，而它原先挡在窗口前面——用户看到的不是「慢」，是「双击图标后毫无反应」。双击关联文件那一路径仍保持同步授权，不受影响。

## 已知限制

- 首次点开某类文档时可能有一次极短的空档（对应内核 chunk 现取）；空闲预载已把大部分抹平，冷启动后立刻点开时仍可能感到一拍。
- 上一版（v0.6.0-patch.1）发布说明里写的「`0.6.0-patch.1` 与 `0.6.0` 会被判等，老用户收不到升级提示」这句是错的：应用内比较按数字段逐位比，第四段的 `1` / `2` 大于缺省的 `0`，装了 v0.6.0 与 v0.6.0-patch.1 的用户都会正常收到本次升级提示。
