# 码克 v0.6.1

这一版集中修预览区：HTML 预览现在能跑页面自带的脚本，渲染模型重写一遍（顺手解决结尾空白、晃屏和切过来白一下），预览工具条三处收成一份并接进 F11 全屏，图片预览修掉「放大过 100% 没反应」并支持放大后拖动查看。

## HTML 预览终于会执行页面脚本

- **现象**：预览一份靠滚动入场动画显影的网页，标题和按钮都在，图以下整片空白。
- **根因有两层**：`iframe` 的 `sandbox` 没放开脚本是一层；更隐蔽的是 **`srcdoc` 文档继承主窗口的 CSP**（`script-src 'self'`），所以光把 `allow-scripts` 加上仍然一行脚本都不跑。
- **改法**：预览源码先落到应用自己的配置目录，再用 asset 协议 URL 加载——只有真实 URL 加载才有独立的 policy container，而 asset 协议的响应不带 CSP 头。主窗口的 CSP 一个字没放松。
- **安全边界按不可信内容对待**：预览的是磁盘上任意一份 HTML，`sandbox` 只给 `allow-scripts`，不给 `allow-same-origin`，文档因此落在 opaque origin —— 读不到应用 DOM、没有 cookie 与本地存储，也带不走文件授权范围；表单提交、开新窗口、把预览面板导航走同样被禁。
- 预览用的临时文档是用户文档的明文副本，随应用启动统一清理，不跨会话留存。

## 渲染模型重写：页面自己滚

- **结尾一长段空白**：原先按「内容 scrollHeight」撑盒、由外层统一滚，而 `documentElement.scrollHeight` 的下限就是盒高本身——早期一次超测（CSS 还没就位）就把盒锁死在那个虚高值上，再也缩不回来。
- **快速滚动闪白**：几千像素高的 iframe 被外层滚动条拖着走，内层来不及向前光栅化。
- 现在 **iframe 恒等于面板尺寸、滚动交给页面自己**，两条一起消失；顺带修好一条副作用——文档自己不滚时，页面里的 `position:sticky` 导航等于失效，现在它真粘住了。
- **缩放不再重载预览**：改由页面内一条消息置根元素 `zoom`，等同浏览器 Ctrl+滚轮语义，调档位是即时的。
- **切过来不白一下**：iframe 挂上时会先铺一层白再画页面，现在按住到首帧画完再 0.18s 淡入；只管挂载后第一次，分栏里边打字边刷新不会跟着闪。
- **滚动条与应用对齐**：不少网页自带 `*{scrollbar-width:thin}`，浏览器一见标准属性就把 `::-webkit-scrollbar` 整段忽略，预览里就变成一条系统浅色条；现在先把根元素复位，再画与应用同色的轨道（透明轨道会透出 iframe 元素自己的白底）。

## 预览工具条收成一份，并接进全屏

- 图片 / HTML / SVG 三处原先各写一套按钮，现在统一成同一份定稿：`− 读数 + 实际尺寸 [适应窗口] 系统打开 全屏`。
- **预览类标签的 F11 以前是静默失效的**：全屏状态现在与代码引擎共用一份，工具条按钮、F11、标签右键「全屏」三条入口读同一份，按任一入口另外两边跟着变；全屏图标随状态在放大 / 还原之间换向。
- **HTML / SVG 分栏可拖宽**：源码区与预览区之间那条分隔线现在能按住左右拖（15%~85%），切走再切回保持。
- 三处缩放档位统一为 5% 一档。

## 图片预览两处修复

- **放大过 100% 就没反应**：图片是 flex 容器里的子项，默认允许收缩，`width:N%` 被压回容器宽度——实测 100% 到 300% 渲染宽度恒定不变。取消收缩后放大正常跟手，超出部分由预览区自己滚动。
- **放大后支持拖动查看**：关掉「适应窗口」后按住左键即可平移，光标在抓取与拖动之间切换；不影响适应窗口态的正常浏览。

## SVG 预览

- 「适应窗口」现在允许放大（原先只缩不放），小图能铺满面板，与图片预览同口径；关掉即回 100% 实际尺寸。

## 已知限制

- 预览文档落在 opaque origin：少数依赖 `localStorage` 的网页在预览里会拿不到存储而报错，这类页面请用工具条上的「系统打开」在浏览器里看。
- 预览里点外链不会开新窗口（刻意禁掉弹窗与顶层导航）。
- 本版改动以无头实测与本机自测为主，HTML 预览的脚本执行与安全边界建议按你的实际文档再过一遍。
