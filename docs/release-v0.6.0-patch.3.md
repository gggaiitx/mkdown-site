# 码克 v0.6.0-patch.3

这一版做两件事：把 macOS「打开文件」里那道硬白名单拆掉（顺带把拖入、另存为、重命名的类型口径统一到一个真相源），以及把纯文本从「代码」这套说法里摘出来、给代码/文本引擎补上右键自动换行。

## 「打开文件」不再只列 Markdown

- **根因**：rfd 的 macOS 后端把所有过滤器的扩展名摊成一个数组交给 `NSOpenPanel.setAllowedFileTypes`——那是只认扩展名的**硬白名单**，`*` 在其中不是通配符，而且打开面板没有可切换的下拉框。所以「支持类型 + 所有文件兜底」这套写法在 Mac 上等于永久限制，`.txt` / `.mh` / 代码文件在面板里全被灰掉就是这么来的。
- **macOS 一个过滤器都不加**：rfd 在过滤器为空时根本不调 `setAllowedFileTypes`，面板即全放开。顺带解掉 `Makefile`、`LICENSE`、`.gitignore` 这类无扩展名文本——扩展名白名单永远表达不了它们，而它们本就是可打开的文本。
- **Windows / Linux**：默认选中「所有文件」，另给「码克文档（*.md *.mh）」作可选收窄；Word 反转选 `.docx` 仍按窄列表过滤，三端一致。
- **能开什么不由对话框判**：选中之后统一交前端 `routeByType`，以 Rust 侧的文本探测与预览类型探测为唯一真相源——文本进编辑器，docx/xlsx/图片/PDF 开应用内预览标签，其余交系统默认程序。
- **两条新单测守住这条不变式**：对话框敢列出来的类型，后端必须真的受理；图片组名单与预览判定必须一致。漏一个就是 Mac 上「txt 选不中」那类事故。

## 拖入、单击与另存为的口径统一

- **拖拽不再自带一份扩展名白名单**：那份名单曾把 docx / xlsx / 图片 / PDF 挡在门外，而它们在目录树里点击是能开预览的。现在拖入逐个走后端的类型分流，只有应用内确实开不了的才计入提示。
- **目录树单击与拖入不会误启外部程序**：分流结果补了「应用内开不了」这一态，交系统默认程序只发生在双击与「打开文件」对话框这类显式选择上。
- **另存为跟着标签的真实类型给默认扩展名**：三引擎之后不再一律落 `.md`——`.md` 标签存成 `.txt` 不会被强扭回去；另存之后按新扩展名重算引擎。
- **重命名改了扩展名，引擎跟着换**：`a.md` 改成 `a.txt` 不该还留在 Markdown 内核里，反向亦然；同类型改名零额外探测。
- **扩展名名单收拢到 Rust 一处**：检索原先自己抄的那份文本类型名单漏了 `svg`（编辑器能开能存，搜索里却隐身），`sqlite` 同时挂在文本与二进制两份名单里；现在统一按「二进制优先」判定。

## 纯文本不再叫「代码」

- `.txt` / `.log` / `.csv` / `.tsv` 走的是代码引擎，但「搜索代码 / 复制代码 / 粘贴代码」这套说法对它不成立：这三项在纯文本标签里改成**搜索文本 / 复制文本 / 粘贴文本**，复制完成的提示同步改成「文本已复制到剪贴板」。
- `.json` / `.html` / `.svg` 等仍按「代码」口径，Markdown 与 `.mh` 的菜单不变。

## 代码/文本引擎的自动换行

- 右键菜单新增**自动换行**，默认关：不点时长行照旧横向滚动，点开才折行，再点回滚。长 URL、长日志此前只能拖着横向滚动条一点点挪。
- 切换只重配 CodeMirror 的一个 Compartment：不重建编辑器、不动撤销栈，光标与滚动位置都保持原位。
- 这一项只出现在代码/文本引擎的标签上——Markdown 编辑窗格的换行由内核恒开，摆个开关是假选项。
- 开关状态存进新的设置项 `codeLineWrap`，与旧的 `wordWrap` 分开：后者出厂即为 `true` 且早已写进用户的 settings.json，拿它做「默认关」的开关会一直读出旧值。

## 已知限制

- `codeLineWrap` 是本版新增的后端设置字段：升级前那份 settings.json 里没有它，首次读取按默认值（关）处理，之后正常持久化。
- macOS 的「打开文件」面板现在全类型可选：选到应用内确实开不了的文件时，会按「交系统默认程序」或「提示无法打开」处理，不会静默失败。
- 应用内检查更新按数字段逐位比，`0.6.0-patch.3` 的第四段大于 `patch.2` / `patch.1` / 缺省的 `0`，装了这三版的用户都会正常收到本次升级提示。
